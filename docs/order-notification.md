# Order notification — "NEW ORDER — ACTION REQUIRED"

Reproduces the Lion Elite Wellness store's internal order-notification email and
makes it **brand-parameterized** so Lion Elite Beauty gets the identical system.
It is an **internal owner alert** (not customer outreach) and never emails the
customer automatically — the "Send Receipt" button is a link the owner clicks.

## Why the Beauty site went silent

The Wellness "NEW ORDER" email is generated by the Wellness **Orchids store's
checkout backend** — it is NOT in any GitHub repo (the Wellness site repo holds
only static/data files plus a downstream *inventory-sync* workflow). The Beauty
Orchids store simply never had that checkout → email notification built, so no
alert fired on the serum order. There is no file to copy between repos; the
notification has to be (re)created for the Beauty store.

## What this module gives you

`lib/orders/order-notification.js`:
- `normalizeOrder(source, payload, { brandKey })` — turns a Shopify order
  webhook or a Stripe checkout.session/payment_intent into a common order shape,
  with a brand-prefixed order id (`LEW-…` / `LEB-…`).
- `renderOrderNotificationHtml(order, { brandKey, receiptActionUrl })` — the
  exact email design (gold header, INTERNAL NOTIFICATION, order id, Payment via
  …, Send-Receipt button, customer + ship-to, line-items table).
- `buildOrderNotification(...)` — `{ subject, html, text }`; subject keeps the
  `🛒 New Order` convention so an inventory-sync job can still find it.

Sample (synthetic): `content/email-templates/order-notification/beauty-sample.html`.

## Two ways to turn it on for Beauty

**Option A — rebuild in the Beauty Orchids store (fastest, mirrors Wellness).**
Have the Beauty store do exactly what Wellness does: on a paid Stripe order,
email `beauty-sample.html`'s HTML (Beauty branding) to your ops inbox with
subject `🛒 New Order — Lion Elite Beauty — {orderId}`. This is an Orchids
builder action (owner/Orchids task); hand them this template as the spec.

**Option B — own it in LionOS (durable, both sites from one place).**
Point each store's **Stripe webhook** (`checkout.session.completed`) at the
LionOS integration gateway (`/webhooks/stripe`). A worker step calls
`buildOrderNotification('stripe', event.data.object, { brandKey })` and emails
the owner. Enable behind:
- `ORDER_NOTIFY_ENABLED=true`
- `OWNER_ORDER_NOTIFICATION_EMAIL` (where alerts go)
- an email provider (reuse `RESEND_API_KEY` + a from address)

Fail-closed: with those unset, nothing sends. Claude does not flip these or add
the email/Stripe accounts.

## Note on the inventory sync

The Wellness repo's `.github/workflows/order-inventory-sync.yml` reads
`🛒 New Order` emails to decrement `public/data/current-inventory.json`. If you
want the same stock-sync for Beauty, that workflow **is** copyable to the Beauty
site repo (swap `orders@lionelitewellness.com` → the Beauty orders inbox and the
product aliases). Ask and I'll port it.
